# Splunk HEC sandbox

Local Splunk Enterprise (free dev license) **fronted by an nginx instance acting as a local ALB**. The chain mirrors the production AWS Fargate target shape exactly — same image, same wire protocol on each hop, only the TLS-terminator-as-ALB layer changes.

```
                              ┌──────────────────────────────────────┐
                              │            nginx-alb                 │
   Tier 1: laptop client ─┐   │  :8443 HTTPS (self-signed dev cert)  │
                          ├──▶│                                      │
   Tier 2: ngrok agent ───┘   │  :8080 HTTP  (consumed by ngrok)     │
                              └──────────────────┬───────────────────┘
                                                 │ HTTP
                                                 ▼
                              ┌──────────────────────────────────────┐
                              │      splunk (HEC :8088, HTTP)        │
                              └──────────────────────────────────────┘

   Tier 3 (prod):  TEE  ── HTTPS (ACM cert) ──▶  ALB  ── HTTP ──▶  ECS task: splunk
```

`nginx-alb` is the dev-time stand-in for the AWS ALB. **Exactly one TLS termination at the front of the chain in every tier; backend wire protocol is always plain HTTP.**

## Tier 1 — localhost smoke test (~3 s, no cloud)

```bash
cp .env.example .env       # change SPLUNK_PASSWORD / SPLUNK_HEC_TOKEN if you like
docker compose up -d
docker compose logs -f splunk | grep -m1 "Ansible playbook complete"   # ~2 min first boot
```

When healthchecks flip to `healthy`:

- **Splunk Web UI:** `http://localhost:8000`  →  `admin` / `<SPLUNK_PASSWORD>`
- **HEC ingest (HTTPS via nginx-alb):** `https://localhost:8443/services/collector`  →  `Authorization: Splunk <SPLUNK_HEC_TOKEN>`
- **Direct HEC (HTTP, debug only):**    `http://localhost:8088/services/collector` (bypasses nginx)
- **REST API:**                          `https://localhost:8089` (smoke test queries this)

> The HTTPS listener uses a **self-signed dev cert** generated by `nginx/entrypoint.sh` on first boot (stored in the `nginx_certs` named volume — survives `docker compose restart`, regenerates on `docker compose down -v`). Set `"extra": {"verify_ssl": "0"}` in your `--siem-config` JSON so clients skip cert verification.

```bash
python ../scripts/smoke_splunk.py
#   3 events sent, 3 events found in Splunk index=tee_crafter, p50 ~8 ms — PASS
```

The smoke test posts through nginx-alb's HTTPS listener, exercising the full TLS-termination + reverse-proxy + HEC ingest chain.

## Tier 2 — real cloud TEE → laptop Splunk via ngrok

The TEE runs in AWS / GCP / Azure; your laptop's `:8443` isn't reachable from the cloud. ngrok publishes a public HTTPS URL (real Let's-Encrypt cert at its edge) and forwards plain HTTP to nginx-alb's `:8080` listener inside the docker network. The same nginx ALB is exercised in this tier — you're really just exposing it to the public internet via ngrok.

```bash
# 1. Free ngrok account → copy authtoken
echo "NGROK_AUTHTOKEN=<paste>" >> .env

# 2. Bring up Splunk + nginx-alb + ngrok together
docker compose --profile ngrok up -d

# 3. Render a TEE-Crafter siem-config pointed at the live ngrok URL
python ../scripts/make_remote_splunk_siem_config.py
# -> wrote siem-sandbox/configs/splunk-via-ngrok.json
#    endpoint = https://abc-123.ngrok-free.app/services/collector

# 4. Deploy a real SNP-AWS TEE that ships attestation events at your laptop
cd ../..
tee-crafter deploy-container \
    --tee-platform snp-aws \
    --ami-id "$SNP_AMI_AWS" \
    --source ./examples/docker_flask_api \
    --siem splunk-hec \
    --siem-config siem-sandbox/configs/splunk-via-ngrok.json \
    --deploy --auto-approve --teardown

# 5. Watch events in real-time:
#    open http://localhost:8000  →  Search & Reporting
#    SPL:  index=tee_crafter | head 50
```

Tier 2 has **two TLS hops total**: ngrok's Let's-Encrypt cert at the public edge, and… no second termination — ngrok forwards plain HTTP to nginx, which forwards plain HTTP to Splunk. The TEE only sees the ngrok cert. No `verify_ssl=0` needed (real CA-signed cert), so the generated config omits that knob.

Free-tier ngrok rotates the public URL on each container restart. Re-run `make_remote_splunk_siem_config.py` after `docker compose restart ngrok`. Paid ngrok plans get reserved domains.

## Tier 3 — production parity (Fargate + ALB + ACM)

Replace nginx-alb with AWS ALB. Same Splunk image, same `:8088` HTTP backend, same exporter code path. Only the URL the customer puts in their `siem-config` JSON changes:

| | Tier 1 / Tier 2 (sandbox) | Tier 3 (Fargate prod) |
|---|---|---|
| Image | `splunk/splunk:latest` | `splunk/splunk:latest` |
| HEC backend | plain HTTP `:8088` | plain HTTP `:8088` |
| TLS terminator | nginx-alb (self-signed) or ngrok edge (Let's Encrypt) | ALB + ACM cert |
| Token storage | `.env` | AWS Secrets Manager → ECS task secret |
| `endpoint` in `siem.json` | `https://localhost:8443/...` or `https://*.ngrok-free.app/...` | `https://splunk-hec.example.com/services/collector` |
| `verify_ssl` | `0` (Tier 1, self-signed) / unset (Tier 2, real cert) | unset (real cert) |
| `egress_mode` | `none` / `public` | `public` + ALB CIDR in `egress_allowlist_cidrs` |

Fargate Terraform recipe (`terraform/fargate/` — ECS service + ALB + ACM + Secrets Manager) is planned. Ask when you want it scaffolded.
