# Linux/x86_64 CUDA stack pulled in transitively by torch==2.6.0.
# Listed explicitly (without environment markers) so `pip download` on a
# macOS / arm64 deployer still fetches them for the linux_x86_64 target —
# pip evaluates markers against the running interpreter even when
# --platform is forced.
#
# These are the versions the base image (pytorch/pytorch:2.6.0-cuda12.4-
# cudnn9-runtime) actually has installed, read out of it with
# `importlib.metadata` rather than copied from torch's PyPI metadata: the
# published wheel on PyPI is the cu128 build, so its pins name different CUDA
# versions than the cu124 image we run.  Matching the image is what keeps the
# `pip install -r requirements.txt` step a no-op instead of a 2.5 GB reinstall.
