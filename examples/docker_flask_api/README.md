# Docker Flask API — Container-in-TEE Example

A minimal Flask JSON API deployed as a confidential container across all 10 TEE platforms.

## What this demonstrates

- **Your Dockerfile runs as-is** — your Docker container runs as-is inside the TEE
- **Attestation + provenance** — TEE-Crafter terminates RA-TLS in the platform attested ingress proxy
- **Cross-cloud** — same command structure works on AWS, Azure, and GCP

## Bake an image once (per platform)

```bash
tee-crafter internal bake-ami --tee-platform <platform>
# prints AMI / Azure image / GCP image URI -> use it as <IMAGE_ID> below
```

## Deploy commands

All deploys use the platform's default instance type (pass `--instance-type`
to pick another — see `tee-crafter list-instances`) and the mandatory
`--ami-id <IMAGE_ID>` so the VM boots straight into a hardened, locked-down
image (no first-boot egress).

### Nitro (AWS)

```bash
tee-crafter deploy \
  --source ./examples/docker_flask_api \
  --tee-platform nitro-aws \
  --ami-id <IMAGE_ID> \
  --persistent \
  --deploy --auto-approve --teardown
```

## Comprehensive deploy — `.env` + syslog SIEM + BYOK

This example ships a [`.env`](./.env) with `PORT`, `ENVIRONMENT`, and an
`API_TOKEN`. The full fail-closed production shape seals the `.env` with a
customer-managed key, streams continuous-attestation events to a syslog/CEF
SIEM, and runs as a long-lived attested service. The `configs/` paths below are
**generated** by the sandbox helper scripts, not checked in — run
`apps/cli/siem-sandbox/scripts/make_remote_syslog_siem_config.py` and
`apps/cli/byok-sandbox/generate_byok_config.py` first:

```bash
# AWS — AMD SEV-SNP
tee-crafter deploy \
  --source ./examples/docker_flask_api \
  --tee-platform snp-aws \
  --ami-id <IMAGE_ID> \
  --persistent --service-profile long-lived \
  --secrets-env ./examples/docker_flask_api/.env \
  --siem syslog-cef --siem-config ./apps/cli/siem-sandbox/configs/syslog-via-ngrok.json \
  --byok aws-kms     --byok-config ./apps/cli/byok-sandbox/configs/byok-snp-aws.json \
  --deploy --auto-approve
```

Swap the cloud by changing three things only — `--tee-platform`, `--ami-id`,
and `--byok` provider/config:

(All `configs/*.json` paths below are generated by the sandbox helpers, not
checked in.)

| Cloud | `--tee-platform` | `--byok` | `--byok-config` (generated) |
|-------|------------------|----------|------------------|
| AWS (Nitro) | `nitro-aws` | `aws-kms` | `apps/cli/byok-sandbox/configs/byok-nitro-aws.json` |
| AWS (SNP) | `snp-aws` | `aws-kms` | `apps/cli/byok-sandbox/configs/byok-snp-aws.json` |
| GCP (SNP) | `snp-gcp` | `gcp-kms` | `apps/cli/byok-sandbox/configs/byok-gcp.json` |
| Azure (SNP) | `snp-azure` | `azure-skr` | Hand-provisioned, not generated — the vault, exportable key and release policy are yours. Follow [azure_setup.md](../../docs/azure_setup.md#secure-key-release-on-azure----byok-azure-skr) and set `TEE_CRAFTER_MAA_ENDPOINT`. Use `azure-skr`, not `azure-kv`: Key Vault wraps the released key to a vTPM-sealed key no Python process can unwrap. A release **has** completed on live `snp-azure` hardware — see [byok.md](../../docs/byok.md). |

- **With `--byok`** the `.env` is envelope-sealed at deploy and decrypted **only
  inside the attested enclave** (tmpfs `/run/tee_crafter/app.env`); the cleartext
  never touches disk or the image, and release is bound to the bake-time pinned
  launch measurement.
- **Without `--byok`** the `.env` is baked into the **measured** image — fine for
  non-secret config, but use BYOK for real secrets.
- Drop `--siem` / `--byok` / `--secrets-env` to peel back layers; add `--teardown`
  for an ephemeral smoke test.

Either way the values surface to the app as ordinary environment variables
(`os.environ`), so no app changes are needed.

### Verify `.env` injection

`app.py` echoes the injected config so you can prove delivery end-to-end. A
**GET** `/health` (or `/`) returns a non-secret proof (it never returns secret
values, only presence booleans + the `APP_BANNER` marker from the `.env`):

```bash
curl https://<attested-endpoint>/health
# {"status":"ok","banner":"tee-crafter .env injection OK",
#  "environment":"production","api_token_loaded":true,"env_injection_ok":true}
```

If the `.env` never arrived, `banner` is `"<.env NOT injected>"` and
`env_injection_ok` is `false`. The same `env_injection` block is included in
every authenticated `POST` response, and a startup line is printed to the
container logs.

## How it works

1. TEE-Crafter builds your Docker image locally
2. For **Nitro**: merges it with the Nitro runtime into an EIF (PCRs bind to the merged image)
3. For **TDX/SNP CVMs**: saves the image as a tarball, uploads it to the confidential VM, and runs it alongside the RA-TLS attestation proxy
4. For **SGX**: wraps the Python app with Gramine for enclave execution
5. Client connects via RA-TLS, verifies attestation, and sends encrypted requests
